## 第1章 漏洞概述与风险评级

本次实验在 Flask Web 应用的动态页面加载功能中发现了路径穿越漏洞（Path Traversal），属于文件包含类安全漏洞。攻击者可通过构造特殊的页面名称参数，越权读取服务器上的任意文件。

| 评估项 | 评级/评分 |
|--------|-----------|
| CVSS 3.0 | 7.5（高危） |
| 攻击向量 | 网络远程攻击（AV:N） |
| 攻击复杂度 | 低（AC:L） |
| 影响范围 | 敏感文件泄露（C:H/I:N/A:N） |

### 漏洞思维导图

```
路径穿越：/page?name=../../../etc/passwd → 读取系统密码文件 → 敏感信息泄露
文件读取：/page?name=../app.py           → 读取应用源码       → 代码审计
正常访问：/page?name=help                → 显示帮助页面       → 正常功能
```

## 第2章 路径穿越漏洞原理

### 2.1 什么是路径穿越

路径穿越（Path Traversal）是指攻击者利用文件路径拼接时的安全缺陷，通过使用 `../` 等特殊字符跳出受限目录，访问或读取服务器上的任意文件。

### 2.2 攻击原理

```
正常访问：
  /page?name=help
  → os.path.join("pages", "help")
  → pages/help.html
  → 读取 pages 目录下的 help.html ✅

路径穿越攻击：
  /page?name=../../../etc/passwd
  → os.path.join("pages", "../../../etc/passwd")
  → pages/../../../etc/passwd = /etc/passwd
  → 读取了系统密码文件 ❌
```

### 2.3 常见攻击Payload

| Payload | 攻击目标 |
|---------|---------|
| `../app.py` | 读取应用源码 |
| `../../../etc/passwd` | 读取系统用户列表 |
| `../../../etc/shadow` | 读取密码哈希（需root权限） |
| `../.env` | 读取环境变量中的密钥 |
| `../data/users.db` | 读取SQLite数据库文件 |

## 第3章 漏洞分析与复现

### 3.1 漏洞代码

漏洞位于 `app.py` 第 565～591 行（漏洞版本）：

```python
@app.route("/page", methods=["GET"])
def dynamic_page():
    name = request.args.get("name", "").strip()
    # ⚠️ name 直接来自 URL 参数，用户可控
    # ⚠️ 未对 ../ 等路径穿越字符做任何过滤

    pages_dir = os.path.join(os.path.dirname(os.path.abspath(__file__)), "pages")
    file_path = os.path.join(pages_dir, name)         # ❌ 直接拼接用户输入

    if os.path.isfile(file_path):
        with open(file_path, "r", encoding="utf-8") as f:
            page_content = f.read()                    # ❌ 读取任意文件
    else:
        file_path_html = file_path + ".html"
        if os.path.isfile(file_path_html):
            with open(file_path_html, "r", encoding="utf-8") as f:
                page_content = f.read()
```

**问题分析：**

| 问题 | 说明 |
|------|------|
| 未校验输入 | `name` 参数未做任何过滤，`../` 可自由使用 |
| 未校验路径边界 | `os.path.join()` 不阻止路径穿越，`../` 会正常跳出目录 |
| 直接读取并显示 | 文件内容读取后直接通过 `{{ page_content \| safe }}` 渲染到页面 |
| 无权限检查 | 未登录用户也可访问 `/page` 路由 |

### 3.2 漏洞验证一：读取应用源码

**请求：**
```
GET /page?name=../app.py
```

**实际结果：** 页面直接显示了 `app.py` 的完整源代码。攻击者可通过读取源码进行代码审计，发现更多安全漏洞。

**攻击效果：**
- 获取数据库连接参数
- 获取 SECRET_KEY 配置
- 发现其他漏洞点
- 分析业务逻辑

### 3.3 漏洞验证二：读取系统密码文件

**请求：**
```
GET /page?name=../../../etc/passwd
```

**控制台输出：**
```
page-content">
    root:x:0:0:root:/root:/usr/bin/zsh
    daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
    bin:x:2:2:bin:/bin:/usr/sbin/nologin
    ...
```

**攻击效果：** 成功读取了 Linux 系统 `passwd` 文件，获取了系统所有用户的账户信息。

### 3.4 漏洞验证三：正常功能不受影响

**请求：**
```
GET /page?name=help
```

**正常返回：** 帮助中心页面内容正常显示，不影响正常用户使用。

## 第5章 修复方案详解

### 5.1 路径边界校验（Path.resolve）

**核心思路：** 使用 `Path.resolve()` 将拼接后的路径标准化，然后用 `startswith()` 检查是否仍在 `pages` 目录内。

```python
from pathlib import Path

pages_dir = Path("pages").resolve()  # 获取 pages 目录的绝对路径

# 用户请求的路径
candidate = (pages_dir / name).resolve()

# 检查是否在 pages 目录内
if not str(candidate).startswith(str(pages_dir)):
    return "非法的页面路径"
```

**修复原理：**

| 步骤 | 说明 |
|:----:|------|
| 1 | 定义合法的 pages 目录路径 |
| 2 | 将用户输入的 name 拼接到 pages 目录后 |
| 3 | 用 `Path.resolve()` 解析 `..` 和符号链接，得到绝对路径 |
| 4 | 用 `startswith()` 验证最终路径是否在 pages 目录范围内 |

### 5.2 修复后代码

```python
@app.route("/page", methods=["GET"])
def dynamic_page():
    name = request.args.get("name", "").strip()
    if not name:
        return render_template("index.html", page_error="未指定页面名称"), 400

    page_content = None
    page_error = None

    # ✅ 使用 Path.resolve() 校验路径在 pages 目录内
    pages_dir = Path("pages").resolve()
    candidate = (pages_dir / name).resolve()

    if not str(candidate).startswith(str(pages_dir)):
        page_error = "非法的页面路径"
    elif candidate.is_file():
        try:
            with open(str(candidate), "r", encoding="utf-8") as f:
                page_content = f.read()
        except Exception:
            page_error = "读取页面失败"
    else:
        # 尝试加 .html 后缀
        candidate_html = (pages_dir / (name + ".html")).resolve()
        if str(candidate_html).startswith(str(pages_dir)) and candidate_html.is_file():
            try:
                with open(str(candidate_html), "r", encoding="utf-8") as f:
                    page_content = f.read()
            except Exception:
                page_error = "读取页面失败"
        else:
            page_error = "页面不存在"

    return render_template("index.html", page_content=page_content, page_error=page_error)
```

## 第8章 安全编码规范总结

### 路径穿越防御原则

| 原则 | 说明 |
|:----:|------|
| **白名单校验** | 如果可能，使用白名单限制可访问的页面名称，而不是依赖路径检查 |
| **路径标准化** | 始终使用 `Path.resolve()` 或 `os.path.realpath()` 将路径标准化后再使用 |
| **边界检查** | 确保最终访问的文件路径在预期的根目录范围内（`startswith` 检查） |
| **避免拼接** | 不要直接将用户输入拼接到文件路径中，使用白名单映射 |
| **最小权限** | 应用进程使用最小权限运行，限制可读取的文件范围 |

### 安全建议

1. **永远不要信任用户输入** — 文件路径、URL参数、表单数据都是潜在攻击面
2. **使用白名单** — 对于页面加载功能，最安全的方式是使用白名单映射，而非动态拼接路径
3. **纵深防御** — 即使路径校验通过，也应限制应用进程的文件系统权限
4. **对敏感操作记录日志** — 异常的文件访问请求应被记录，便于安全事件追溯
5. **最小暴露原则** — 不要在页面中直接渲染文件内容（`{{ content | safe }}`），考虑对输出进行转义
