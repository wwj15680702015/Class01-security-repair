## 第1章 漏洞概述与风险评级

本次实验在密码修改功能中发现了多个安全漏洞，涉及CSRF、垂直越权和逻辑缺陷。

| 漏洞类型 | 漏洞名称 | 严重度 | CVSS |
|---------|---------|:------:|:----:|
| CSRF | 修改密码接口无CSRF Token保护 | 高危 | 8.8 |
| 垂直越权 | 任意用户可修改他人密码 | 高危 | 8.6 |
| 业务逻辑 | 无需原密码即可修改密码 | 高危 | 7.5 |
| 输入验证 | 无密码强度校验 | 中危 | 5.3 |
| 逻辑缺陷 | 确认密码字段后端未使用 | 低危 | 3.1 |

### 漏洞思维导图

```
CSRF无保护：  攻击者构造钓鱼表单 → 已登录用户点击 → 密码被改
垂直越权：    alice登录 → 提交username=admin → 管理员密码被改
无需原密码：  知道用户名 → 任何人都能改密码 → 账号失陷
密码强度：    设置"123" → 弱密码 → 易被暴力破解
确认密码：    前端校验可绕过 → 两次输入不一致 → 用户自己锁自己
```

## 第2章 漏洞原理与代码分析

### 2.1 漏洞一：CSRF 无保护（高危）

**漏洞代码（app.py 第 607 行）：**

```python
@app.route("/change-password", methods=["POST"])
@csrf.exempt  # ❌ 跳过了 CSRF 保护
def change_password():
```

**攻击场景：**
1. 攻击者在第三方网站构造一个自动提交的隐藏表单，action 指向目标网站的 `/change-password`
2. 诱导已登录目标网站的用户访问该页面
3. 浏览器自动携带用户的 session Cookie 发送 POST 请求
4. 密码被成功修改，用户无法再登录

### 2.2 漏洞二：任意修改他人密码（高危）

**漏洞代码（app.py 第 612～620 行）：**

```python
username = request.form.get("username", "").strip()
new_password = request.form.get("new_password", "")
# ❌ username 来自表单，用户可控
# ❌ 未检查当前登录用户和 username 是否一致

if username in USERS:
    USERS[username]["password_hash"] = generate_password_hash(new_password)
    # ❌ 直接修改了任意用户的密码
```

**攻击场景：**
1. 普通用户 alice 登录系统
2. 使用 Burp Suite 拦截修改密码请求
3. 将 `username=alice` 改为 `username=admin`
4. 提交后管理员 admin 的密码被修改为 alice 设置的密码
5. alice 现在可以用新密码登录 admin 账号

### 2.3 漏洞三：无需原密码（高危）

**漏洞代码：** 整个 `change_password()` 函数没有任何验证原密码的环节。

```python
def change_password():
    # ❌ 没有验证原始密码
    # ❌ 没有验证身份（如短信验证码）
    USERS[username]["password_hash"] = generate_password_hash(new_password)
```

**攻击场景：** 只要攻击者通过 CSRF 或垂直越权到达该接口，无需知道任何人的原密码即可修改成功。

### 2.4 漏洞四：无密码强度校验（中危）

```python
new_password = request.form.get("new_password", "")
# ❌ 没有检查密码长度、复杂度
```

攻击者可设置 `new_password=1` 这样的弱密码，容易被暴力破解。

### 2.5 漏洞五：确认密码字段后端未使用（低危）

前端表单包含 `confirm_password` 字段，但后端完全没有读取和使用它。

```python
# ❌ 后端没有读取 confirm_password
# ❌ 没有比对 new_password 和 confirm_password
```

如果用户在前端输入了两个不同的密码，前端校验可以跳过（用curl直接发送请求），导致用户密码被设为自己不知道的值。

## 第3章 漏洞验证（curl实操）

### 3.1 垂直越权验证：alice 修改 admin 密码

```bash
# 1. 以 alice 登录获取 cookie
curl -c /tmp/alice.txt -X POST http://target:5000/login \
  -d 'username=alice&password=alice2025'

# 2. 修改管理员 admin 的密码（漏洞版本）
curl -b /tmp/alice.txt -X POST http://target:5000/change-password \
  -d 'username=admin&new_password=admin_hacked'
# ❌ 成功！alice 修改了 admin 的密码

# 3. 用新密码登录 admin
curl -X POST http://target:5000/login \
  -d 'username=admin&password=admin_hacked'
# ✅ 登录成功——账号被夺取
```

### 3.2 CSRF 验证（Burp Suite）

| 步骤 | 操作 |
|:----:|------|
| 1 | 用户登录目标网站 |
| 2 | 攻击者发送钓鱼页面，包含 `<form action="http://target/change-password">` |
| 3 | 用户点击提交（或通过 JS 自动提交） |
| 4 | 浏览器自动携带 session Cookie |
| 5 | 密码被修改为攻击者预设的值 |

### 3.3 无密码强度验证

```bash
curl -b cookies.txt -X POST http://target:5000/change-password \
  -d 'username=admin&new_password=1'
# ✅ 成功！密码被设为"1"
```

## 第4章 修复方案详解

### 4.1 CSRF 保护

**修复方式：** 移除 `@csrf.exempt` 装饰器，表单添加 CSRF Token。

```python
# 修复前
@csrf.exempt
def change_password():

# 修复后
def change_password():
```

```html
<!-- 修复前：表单没有 csrf_token -->
<form method="post" action="/change-password">
    <input type="hidden" name="username" value="...">

<!-- 修复后：表单添加 csrf_token -->
<form method="post" action="/change-password">
    <input type="hidden" name="csrf_token" value="{{ csrf_token() }}">
    <input type="hidden" name="username" value="...">
```

### 4.2 垂直越权修复——身份校验

**核心思路：** 限制用户只能修改自己的密码。

```python
def change_password():
    current_user = session.get("username")
    username = request.form.get("username", "").strip()

    # 只允许修改当前登录用户自己的密码
    if username != current_user:
        print(f"[安全警告] 用户={current_user} 试图修改用户={username} 的密码（已拒绝）")
        return redirect(url_for("profile", user_id=1))
```

### 4.3 确认密码校验

```python
confirm_password = request.form.get("confirm_password", "")

# 确认两次密码一致
if new_password != confirm_password:
    print(f"[安全警告] 用户={username} 两次密码输入不一致")
    return redirect(url_for("profile", user_id=1))
```

### 4.4 密码强度校验

```python
# 密码长度至少 6 位
if len(new_password) < 6:
    print(f"[安全警告] 用户={username} 密码长度不足6位")
    return redirect(url_for("profile", user_id=1))
```

## 第5章 修复前后代码对比

| 对比项 | ❌ 修复前（漏洞版本） | ✅ 修复后（安全版本） |
|--------|-------------------|--------------------|
| CSRF 保护 | `@csrf.exempt` 跳过保护 | 移除 `@csrf.exempt`，表单加 Token |
| 身份校验 | `username` 来自客户端，无验证 | 必须等于 `session["username"]` |
| 原密码验证 | 无 | 由 session 身份验证替代 |
| 密码强度 | 无 | `len(new_password) >= 6` |
| 确认密码 | 后端未使用 | 校验与 `new_password` 一致 |
| 安全日志 | 无 | 记录用户/IP/操作结果 |

### 核心逻辑对比

**修复前（漏洞版本）：**
```python
@app.route("/change-password", methods=["POST"])
@csrf.exempt  # 无CSRF保护
def change_password():
    username = request.form.get("username")  # 来自客户端，可伪造
    new_password = request.form.get("new_password")

    if username in USERS:
        USERS[username]["password_hash"] = generate_password_hash(new_password)
        # 任意用户的密码都被改了
```

**修复后（安全版本）：**
```python
@app.route("/change-password", methods=["POST"])
def change_password():
    current_user = session.get("username")

    if username != current_user:
        return redirect(url_for("profile"))  # 只能改自己的

    if new_password != confirm_password:
        return redirect(url_for("profile"))  # 密码一致性

    if len(new_password) < 6:
        return redirect(url_for("profile"))  # 密码强度

    USERS[username]["password_hash"] = generate_password_hash(new_password)
```

## 第7章 安全编码规范总结

### 密码修改功能安全原则

| 原则 | 说明 |
|:----:|------|
| **CSRF 保护** | 所有涉及状态变更的 POST 请求必须带 CSRF Token |
| **身份验证** | 修改密码必须验证用户身份（原密码 或 session 认证） |
| **资源所有权** | 用户只能修改自己的密码，不能修改他人密码 |
| **密码强度** | 密码必须有最小长度和复杂度要求 |
| **确认机制** | 两次输入一致性能防止用户锁死自己 |
| **审计日志** | 所有密码修改操作都应记录用户、IP、时间 |
