## 第1章 漏洞概述与风险评级

本次实验在 Flask Web 应用中发现了三大类安全漏洞，涉及越权访问和业务逻辑缺陷：

| 漏洞类型 | 漏洞名称 | 严重度 | CVSS |
|---------|---------|:------:|:----:|
| 水平越权 | IDOR - 任意用户资料查看 | 高危 | 7.5 |
| 垂直越权 | 未授权访问管理面板 | 严重 | 9.1 |
| 垂直越权 | 未授权删除用户 | 严重 | 9.6 |
| 业务逻辑 | 商品价格由客户端提交 | 高危 | 8.2 |
| 业务逻辑 | 充值金额未校验正负 | 高危 | 8.2 |

### 漏洞思维导图

```
水平越权(IDOR)：修改URL参数 → 查看他人信息 → 信息泄露
垂直越权：      直接访问/admin → 管理面板暴露 → 可删除任意用户
业务逻辑：      Burp拦截 → 修改price/amount → 低价购/负值充值
```

## 第2章 水平越权漏洞（IDOR）分析与复现

### 2.1 漏洞原理

Insecure Direct Object Reference（IDOR）是指应用在访问资源时，直接使用用户提供的标识符（如 ID），而未验证当前用户是否有权访问该资源。

### 2.2 漏洞代码

漏洞位于 `app.py` 第 395～421 行：

```python
@app.route("/profile", methods=["GET"])
def profile():
    if "username" not in session:
        return redirect(url_for("login"))

    user_id = request.args.get("user_id", "").strip()
    # ⚠️ user_id 直接来自 URL 参数，用户可控
    # ⚠️ 没有验证当前登录用户是否与 user_id 匹配

    cursor.execute(
        "SELECT id, username, email, phone FROM users WHERE id = ?",
        (int(user_id),)
    )
    row = cursor.fetchone()
    ...
    return render_template("profile.html", user=user_info)
```

### 2.3 漏洞验证

**Step 1：** 登录普通用户 alice（密码 alice2025）

**Step 2：** 将 `/profile?user_id=2` 中的 `user_id` 改为 1

```
GET /profile?user_id=1    ← 把2改成1
```

**Step 3：** 页面返回管理员 admin 的完整资料

```bash
# 以 alice 身份查看 admin 的资料
$ curl -b cookies.txt 'http://target:5000/profile?user_id=1'
# 返回：admin / admin@example.com / 13800138000 / 余额 99999
```

### 2.4 攻击效果

任意登录用户可通过修改 URL 中的 `user_id` 参数，查看包括管理员在内的所有用户个人信息（邮箱、手机号、余额），造成大规模信息泄露。

## 第3章 垂直越权漏洞分析与复现

### 3.1 漏洞原理

垂直越权（Privilege Escalation）指低权限用户通过直接访问高权限 URL，获得管理员等高级权限的操作能力。

### 3.2 漏洞点1：未授权访问管理面板

**漏洞代码（app.py 第 480～500 行）：**

```python
@app.route("/admin", methods=["GET"])
def admin_panel():
    if "username" not in session:
        return redirect(url_for("login"))
    # ⚠️ 仅检查了登录，未检查是否为管理员！

    cursor.execute("SELECT id, username, email, phone FROM users ORDER BY id")
    all_users = cursor.fetchall()
    return render_template("admin.html", users=all_users)
```

**漏洞验证：**

```bash
# 普通用户 alice 直接访问 /admin
$ curl -b alice_cookies.txt 'http://target:5000/admin'
# 返回全部用户列表，包含 admin/alice 等全部信息
```

管理面板包含：
- 全部用户的 ID、用户名、邮箱、手机、余额
- 每个用户对应的删除按钮

### 3.3 漏洞点2：未授权删除用户

**漏洞代码（app.py 第 502～526 行）：**

```python
@app.route("/admin/delete-user", methods=["POST"])
def admin_delete_user():
    if "username" not in session:
        return redirect(url_for("login"))
    # ⚠️ 任何登录用户都可以删除任意用户！

    cursor.execute("DELETE FROM users WHERE id = ?", (int(user_id),))
    conn.commit()
    return redirect(url_for("admin_panel"))
```

**漏洞验证：**

```bash
POST /admin/delete-user
Body: user_id=3
→ 用户 ID=3 被永久删除，无需管理员权限
```

### 3.4 攻击效果

普通用户 alice 可以：
1. 访问管理后台查看所有注册用户的信息
2. 删除任意用户（包括管理员账号）

## 第4章 业务逻辑漏洞——商品价格篡改

### 4.1 漏洞原理

商品价格应由服务器从数据库获取。若价格由客户端表单提交，攻击者可通过 Burp 拦截修改 `price` 参数，以任意价格购买商品。

### 4.2 漏洞代码

**前端表单（shop.html）中的隐藏字段：**

```html
<input type="hidden" name="price" value="{{ product.price }}">
```

**后端处理（app.py 第 535～559 行）：**

```python
@app.route("/cart", methods=["POST"])
def cart():
    product_name = request.form.get("product_name", "未知商品")
    price = request.form.get("price", "0")       # ⚠️ 客户端提交的价格不可信！
    quantity = request.form.get("quantity", "1")

    total = float(price) * int(quantity)
    print(f"[购物车] 商品={product_name} 单价={price} 数量={quantity} 总价={total}")
```

### 4.3 漏洞验证

**Burp 拦截步骤：**

1. 登录后访问 `/shop`，点击 iPhone 15 Pro Max（¥9999）的"加入购物车"
2. Burp 拦截 `POST /cart` 请求
3. 将 `price=9999` 改为 `price=0.01`
4. 转发请求

```
POST /cart HTTP/1.1
...
product_id=1&product_name=iPhone+15+Pro+Max&price=9999&quantity=1
                                                ⚠️ 把price=9999 改成 price=0.01
```

```bash
# curl 验证
$ curl -b cookies.txt -X POST http://target:5000/cart \
  -d 'product_id=1&product_name=iPhone&price=0.01&quantity=1'
# 返回总价 ¥0.01，原价¥9999的商品用1分钱买到
```

### 4.4 攻击效果

攻击者可以通过 Burp Suite 拦截购物请求，将商品价格修改为任意值（如 0.01 元），以极低价格购买高价商品。

## 第5章 业务逻辑漏洞——负值充值

### 5.1 漏洞原理

充值功能直接执行 `balance = balance + amount`，但未校验 `amount` 的正负。攻击者可提交负值来扣减任意用户的余额。

### 5.2 漏洞代码（app.py 第 433～469 行）

```python
@app.route("/recharge", methods=["POST"])
def recharge():
    user_id = request.form.get("user_id", "").strip()
    amount = request.form.get("amount", "").strip()

    # ⚠️ 直接执行 balance + amount，未校验 amount 正负
    USERS[username]["balance"] = USERS[username]["balance"] + amount_float
```

### 5.3 漏洞验证

```bash
# 扣减 alice 余额 100 元
$ curl -b cookies.txt -X POST http://target:5000/recharge \
  -d 'user_id=2&amount=-100'
# alice 的余额从 ¥100 变成 ¥0

# 扣减 admin 余额
$ curl -b cookies.txt -X POST http://target:5000/recharge \
  -d 'user_id=1&amount=-99999'
# admin 的余额从 ¥99999 变成 ¥0
```

### 5.4 攻击效果

攻击者可以通过负值充值接口，任意扣减其他用户的余额，造成经济损失。

## 第6章 修复方案详解

### 6.1 IDOR 修复——验证资源所有权

**核心思路：** 从 session 获取当前用户，与请求的资源所有者比对。普通用户只能查看自己的资料，管理员可以查看所有用户。

```python
@app.route("/profile", methods=["GET"])
def profile():
    user_id = request.args.get("user_id")
    current_username = session.get("username")

    # 查询目标用户的 username
    cursor.execute("SELECT username FROM users WHERE id = ?", (int(user_id),))
    target = cursor.fetchone()

    # 获取当前用户的角色
    cursor.execute("SELECT role FROM users WHERE username = ?", (current_username,))
    current_user = cursor.fetchone()

    if current_user["role"] != "admin" and target["username"] != current_username:
        return "权限不足，无法查看其他用户资料"
```

### 6.2 垂直越权修复——角色校验

**核心思路：** 每个管理功能前检查当前用户的 `role` 是否为 `admin`。

```python
@app.route("/admin", methods=["GET"])
def admin():
    username = session.get("username")
    cursor.execute("SELECT role FROM users WHERE username = ?", (username,))
    user = cursor.fetchone()
    if user["role"] != "admin":
        return "权限不足，仅管理员可访问"
```

同样，`/admin/delete-user` 也必须添加相同的 role 校验。

### 6.3 价格篡改修复——服务端定价

**核心思路：** 价格从数据库查询，不信任客户端提交的值。

```python
PRODUCTS = {
    1: {"name": "iPhone 15 Pro Max", "price": 9999.00},
    2: {"name": "MacBook Pro 16", "price": 19999.00},
}

@app.route("/cart", methods=["POST"])
def cart():
    product_id = request.form.get("product_id")
    quantity = request.form.get("quantity", "1")

    # 价格从数据库查询，拒绝客户端提交的价格
    product = PRODUCTS.get(int(product_id))
    if not product:
        return "商品不存在"
    real_price = product["price"]
    total = real_price * int(quantity)  # 使用真实价格
```

### 6.4 负值充值修复——金额正校验

**核心思路：** 校验 `amount` 必须为正数；验证用户只能给自己充值。

```python
@app.route("/recharge", methods=["POST"])
def recharge():
    amount = float(request.form.get("amount"))

    if amount <= 0:
        return "充值金额必须为正数"

    # 限制只能给自己充值
    current_username = session.get("username")
    cursor.execute("SELECT username FROM users WHERE id = ?", (int(user_id),))
    target = cursor.fetchone()

    if target["username"] != current_username:
        return "只能给自己充值"

    cursor.execute("UPDATE users SET balance = balance + ? WHERE id = ?",
                   (amount, user_id))
```

### 6.5 最小权限原则实现

修复的核心是遵循最小权限原则：

| 原则 | 说明 |
|------|------|
| 不可信客户端 | 服务器不能信任任何客户端提交的权限相关数据 |
| 二次校验 | 每个敏感操作都必须校验身份和权限 |
| 资源所有权 | URL 参数中的 ID 必须与当前用户 session 比对 |
| 服务端定价 | 价格、金额仅从服务端可信源获取 |

## 第8章 安全编码规范总结

| 原则 | 说明 |
|------|------|
| **永不信任客户端** | 用户 ID、价格、金额等关键数据必须来自服务端可信源（数据库/session），不能依赖客户端提交 |
| **二次权限校验** | 每个管理功能、每个敏感操作都必须校验当前用户是否有权执行。仅检查登录不够，必须检查角色 |
| **资源所有权验证** | 用户只能访问属于自己的资源。URL 参数中的 ID 必须与当前用户 session 比对 |
| **业务逻辑边界校验** | 金额必须为正数、库存不能为负。业务逻辑的边界条件必须服务端校验 |
| **最小权限** | 用户只应有完成任务所需的最小权限。管理功能默认不开放，通过 role 显式授权 |

### 攻击流程汇总

| # | 攻击类型 | 操作 | 攻击效果 |
|:-:|---------|------|---------|
| 1 | 水平越权 | 拦截 `/profile` 请求，改 `user_id` 参数 | 查看任意用户信息 |
| 2 | 垂直越权1 | 直接访问 `/admin` | 进入管理面板（无需管理员） |
| 3 | 垂直越权2 | 拦截 `/admin/delete-user` | 删除任意用户 |
| 4 | 价格篡改 | 拦截 `/cart` 请求，改 `price=0.01` | 1 分钱买 iPhone |
| 5 | 负值充值 | 拦截 `/recharge` 请求，改 `amount=-99999` | 清空他人余额 |
